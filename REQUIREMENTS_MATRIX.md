## Known gaps (see README §16 for full detail)

- Vapi live-call path is now wired end-to-end and covered by 7 tests against a mocked HTTP transport, but still unverified against a real account/credentials — see README §16 checklist.
- Frontend now build-verified (`npm install && npm run build` clean, plus a live click-through) and includes browser mic input/output (Web Speech API) and an intro animation. A zero-build plain-HTML console (`backend/app/static/quick_console.html`, served at `GET /console`) also still exists as a Node-free fallback.
- Confirmation-step corrections escalate to a human rather than being auto-resolved (deliberate scope cut).
- ~~Navigating away from the Console page mid-call loses state~~ — **fixed**: the Callbacks page now hands a redialled session to the Console via router navigation state, and Console resumes it (language, session, collected fields) instead of showing a blank form. Found and fixed live while testing the redial flow end-to-end in the browser.
- Multi-language (English/Hindi/Filipino) works fully for the script text (consent, questions, clarification) and for browser STT/TTS. The rule-based extraction fallback has best-effort multilingual keyword/enum-synonym coverage (not full understanding) — a live Claude call handles this natively; see README.
- Network-drop callback/redial is demo-simulated (`POST /voice/simulate-drop`) since there's no live telephony connection to actually drop — in production this would be a Vapi webhook event, not a UI button.
- Full backend suite is now 140/140 passing (`pytest -q` from `backend/`).
- Follow-up spec implemented: `CallEndReason` taxonomy on every terminal call, an append-only `call_events` trail (non-blocking, queryable by lead), minimal RBAC (`X-Demo-Token` header, Agent/Team Lead/Admin) gating transcripts vs. recordings, a `call_recordings` reference-URL table wired to the Vapi webhook (best-effort, field path unverified against a live payload — flagged in `docs/ARCHITECTURE.md` §12), multi-call-per-lead querying + a Console "Call again / Terminate" outcome card, and an immediate "reconnect now?" popup distinct from the existing scheduled-redial path. See `docs/ARCHITECTURE.md` §12 for full detail and what's still unverified (empirical LLM-confidence parity, live Vapi recording payload shape, no crash-durable mid-call session state).
- Generic-question handling (`generic_question` intent, "trained" against `data/synthetic/generic_questions.json`) and a vague-answer guardrail (a free-text field now rejects bare "yes"/"ok"/"sure" instead of storing it as the literal answer) — see `docs/ARCHITECTURE.md` §13.
- Real login (`POST /auth/login`, a genuine Agent/Team Lead/Admin account each, route-guarded frontend), off-topic chatter now correctly rejected instead of being stored as the literal answer (so the existing 2-tries-then-escalate retry ladder actually engages), and a demo recording-simulation endpoint so the storage/RBAC/access-logging pipeline is verifiable without a live Vapi account — see `docs/ARCHITECTURE.md` §14. Full suite: 152/152 passing.
- A date answered across multiple turns (e.g. "20 September" then, separately, "2005") now merges into one complete date instead of each piece being evaluated in isolation and failing — the direct fix for a live-reported near-immediate escalation. See `app/services/date_parsing.py` (`extract_date_components`, `merge_date_components`) and `app/agents/orchestrator.py` (`_handle_date_field_failure`).
- The Console now shows a call-outcome summary (fields collected, turn count, a link into History) and a "Start another call" reset action on every terminal outcome — previously `sessionId` never cleared, so a second call required a full page reload.
- The first capture failure on any field now gets a warmer, name-addressed transition line ("No worries, {first_name} — let's get that sorted...") instead of a flat repeated question, in `en`/`hi`/`fil`.
- Confirmation-step corrections (at the final read-back summary) still escalate to a human rather than being auto-resolved — unchanged, deliberate scope cut, distinct from the new per-field reconfirmation loop above which IS auto-resolved (re-ask, not escalate, on a single decline).
